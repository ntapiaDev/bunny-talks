## Objectif actif

Séparer l’application produit mobile des diagnostics expérimentaux. `index.ts` reste l’entrée standard et installe d’abord l’aléa natif ; sa racine produit minimale est `src/product/App.tsx`. L’entrée `qualification/crypto/entry.tsx` compose l’écran et les scénarios déplacés sous `qualification/crypto/`. Les adaptateurs natifs et coordinateurs réutilisables restent sous `src/infrastructure/crypto`.

La qualification de nouveaux états synthétiques utilise l’identité `fr.bunnytalks.mobile.cryptoqualification`, activée explicitement par `BUNNY_CRYPTO_QUALIFICATION=synthetic`. La configuration historique conserve l’identité standard mais refuse de se résoudre sans `BUNNY_CRYPTO_HISTORICAL_REQUALIFICATION=AUTHORIZED`. Ce garde-fou de configuration ne prouve pas la compatibilité de signature, de compte utilisateur, de trousseau ou de stockage. Aucun build, installation, arrêt forcé ou changement de données historiques n’est autorisé dans l’étape A.

La suite de l’étape vérifie les graphes Metro des deux entrées, les tests de séparation, les tests diagnostiques déplacés, le typage, le lint, le formatage et les contrôles statiques natifs. Un graphe Metro établit la composition JavaScript résolue ; il ne démontre pas les modules natifs inclus dans un APK ou un Mach-O. La requalification historique de l’étape B exigera une autorisation et un plan d’environnement préservant l’identité, la signature, le compte, les bases SQLite, les fichiers associés et les clés SecureStore sans les exporter.

OpenE2EE 14.5.0 et le coffre V1 restent expérimentaux. SEC-CRYPTO-002 et SEC-CRYPTO-003 restent ouverts et bloquants avant production. Le verrou iOS reste fermé aux parcours métier et aux secrets réels. Aucun changement aux transports HTTPS, formats, protocoles ou dépendances n’est prévu dans ce jalon.
