# Prérequis de qualification mobile

Le workspace demande Node 24.7 à 24.x et pnpm 10.34.9. Le manifeste mobile fixe Expo 57.0.25, React Native 0.86.3, React 19.2.3, expo-sqlite 57.0.3 et expo-secure-store 57.0.4. Le Development Build intègre Hermes, SQLCipher via le plugin Expo SQLite, SecureStore et les modules natifs. Préparer les packages depuis la racine avec `pnpm -r --if-present build`. Sur Android, utiliser le SDK et le JDK compatibles avec le projet généré et sélectionner l’émulateur de test par son identifiant ADB. Sur iOS, les workflows Apple définissent la matrice macOS/Xcode et produisent des rapports limités à leur simulateur. Le minimum déclaré est iOS 16.4. Son exécution reste à vérifier.

Pour préparer une réouverture, relever le paquet, la version, le mode de build et le PID initial. Vérifier la présence du témoin assaini avant arrêt forcé, puis sa comparaison au même état sur un nouveau PID. En cas de clé absente ou invalide, exiger le refus sans recréation des données. Utiliser un environnement isolé pour les scénarios d’état neuf. Les noms et le plan de séparation des entrées figurent dans l’[architecture mobile](mobile-architecture.md#isolation-des-diagnostics-cryptographiques).

Les limites de l’ancien SDK restent dans le [rapport de migration](open-e2ee-14-5-migration.md). Le POC 14.4.0 relève de la comparaison. La version expérimentale active est **14.5.0**. La correction après substitution d’identité propre ne clôt ni l’import atomique, ni l’autorisation individuelle et l’anti-rejeu des appareils (SEC-CRYPTO-002 et SEC-CRYPTO-003).
